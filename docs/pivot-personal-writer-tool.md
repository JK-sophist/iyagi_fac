# Pivot Plan: Personal Writer Tool

## 1) 기존 서비스형 구조에서 유지할 기능
- 프로젝트/세션/장면/체크포인트/분기의 핵심 데이터 모델
- `scene-candidates -> execute-scene -> stop` 흐름(자동 진행 금지 원칙)
- 세계관/엔딩 목표/캐릭터/관계 편집 API 및 화면
- 체크포인트 저장/복원/분기 생성 API
- 시뮬레이션 엔진의 결정적(mock) 제공자 및 테스트 기반

## 2) 제거하거나 약화할 기능
- 다중 사용자 서비스 전제 문구(서비스 출시/운영 중심 표현)
- 과금/포인트/SaaS 운영을 암시하는 우선순위
- “자동 생성” 기대를 유발하는 UX 카피
- 워커/인프라를 제품 핵심으로 강조하는 설명

## 3) 개인용 작가 툴로서 새로 필요한 기능
- 자유 메모(아이디어/복선/설정 충돌 후보 기록)
- 장면 상태 관리(채택/보류/폐기)
- AI 추천과 별도로 작가가 직접 장면 목표 입력
- 체크포인트/분기 UX에서 “실험 기록” 맥락 강화
- Markdown/TXT export 골격
- 캐릭터 카드 강화(후속: 장기 목표, 비밀, 말버릇)
- 설정 충돌 경고 정교화(후속: 룰 기반 검사)
- 분기 트리 시각화(후속)

## 4) 1차 리팩토링 범위
- 랜딩/프로젝트 화면 문구를 개인용 워크벤치 톤으로 수정
- 프로젝트 단위 자유 메모 API + 최소 UI 추가
- 장면 단위 상태/작가 메모 저장 API + UI 추가
- 세션 화면에 직접 장면 목표 입력 UI/API 연결
- 프로젝트 Export(Markdown/TXT) 최소 API 추가 + UI 진입점 추가

## 5) 2차 리팩토링 범위
- 분기 트리 시각화 컴포넌트 및 세션 비교 UX
- 설정 충돌 경고 룰 확장(캐릭터/관계/세계관 변화 감지)
- 캐릭터 카드 확장 및 장면/메모 상호 링크
- export 템플릿 고도화(장면 선택 export, 메모 포함 옵션)
- 문서 구조 정비(개인 워크플로우 중심 runbook)

## 6) 현재 구조에서 재사용 가능한 코드
- Backend: `app/api.py`의 프로젝트/세션/체크포인트/분기 엔드포인트
- Backend: `app/services/simulation/*` 오케스트레이션/실행 파이프라인
- Frontend: 프로젝트/세션/체크포인트 페이지와 공통 UI 컴포넌트
- Tests: API 흐름/엔진 테스트 틀(회귀 방지 기반)
- Docs: 시뮬레이션/체크포인트 중심 설명 문서의 핵심 개념

## 7) 예상 리스크
- 인메모리 저장소 특성상 재시작 시 데이터 유실
- scene 상태/메모 추가에 따른 기존 테스트 fixture 불일치 가능성
- export 출력 포맷이 커지면 UI/백엔드 스키마 동기화 필요
- 분기/복원 후 scene 메타데이터 일관성 관리 복잡도 증가
- 개인용 사용 시나리오 다양성으로 UX 요구가 빠르게 확장될 가능성
